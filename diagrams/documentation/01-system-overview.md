# Документация системы Telco Customer Churn ML

## Назначение и границы

Проект представляет собой локальное пакетное исследовательское приложение для анализа данных о клиентах телекоммуникационной компании и проектирования последующего прогнозирования оттока. Пользователь запускает Python-сценарии из командной строки. Данные, отчёты и будущие ML-артефакты хранятся в файловой структуре проекта.

В текущую границу системы не входят постоянно работающий сервер, веб-интерфейс, API, интеграция с CRM и потоковая обработка.

## Текущее состояние

Реализованы:
- `scripts/split_data.py`: формирование `data/initial/initial_60.csv` и четырёх файлов `data/incoming/`, создание манифеста с контрольными хешами;
- `scripts/eda_initial.py`: разведочный анализ начальной выборки, отчёты, проверки и графики;
- хранение исходного набора отдельно от производных выборок;
- версионный контроль проекта средствами Git.

Запланированы:
- автоматическая валидация входящих пакетов;
- единый обучаемый pipeline предобработки и инжиниринга признаков;
- разбиение на Train / Validation / Test для разработки модели;
- обучение, сравнение и независимая оценка моделей;
- сохранение модели и преобразователей;
- пакетное прогнозирование и контроль качества после поступления фактических меток.

Каталоги `models/` и `data/processed/` сами по себе не подтверждают реализацию соответствующих функций.

## Данные и ограничения

Исходный CSV рассматривается как неизменяемый источник. Начальная выборка и incoming-пакеты — производные файлы. Отсутствие достоверных временных меток в исходном наборе не позволяет считать incoming-пакеты реальной временной последовательностью.

`Churn` — целевая переменная, а не предиктор. `customerID` сохраняется для сопоставления записей, но исключается из матрицы признаков. Временная доступность `TotalCharges` на момент прогноза должна быть подтверждена до включения этого поля в основной набор признаков.

## Логические контейнеры

- **Python CLI application** — запуск сценариев подготовки выборок и EDA; будущие задачи валидации, обучения и прогнозирования.
- **Файловое хранилище данных** — исходный CSV, начальная выборка и входящие пакеты.
- **Хранилище отчётов и ML-артефактов** — текущие отчёты и графики, а в целевом состоянии — модель, преобразователи, метрики и прогнозы.

## Взаимодействия

Пользователь запускает локальные команды и просматривает результаты. Исходные данные поступают из статического CSV-набора. CLI читает и записывает файлы в локальной файловой системе. Git/GitHub используется для разработки и версионирования, но не является runtime-компонентом ML-системы.

## Технологические и архитектурные ограничения

- локальный пакетный запуск вместо постоянно работающего сервиса;
- файловое взаимодействие между сценариями;
- неизменяемость исходного CSV;
- воспроизводимые параметры разбиения и манифестирование данных;
- единое сохранённое преобразование признаков для Validation, Test и прогнозирования после реализации ML pipeline;
- явное разграничение реализованных и проектируемых функций.
